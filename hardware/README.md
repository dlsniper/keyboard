# hardware/

KiCad 10 projects for every board in the spec (§2a, §14). Generated by
`tools/gen_kicad.py`; checked by `tools/kicad-check.sh` (ERC + DRC on every
project, then `tools/check_interconnect.py`; reports in `build/kicad-check/`).

The generator always rewrites `lib/`, and only creates project files that are
missing, so schematic and board work is never overwritten.

The core, battery, USB port, link, seam, dial and expansion schematics are written by `tools/sch_core.py`, `tools/sch_battery.py`,
`tools/sch_usb_port.py`, `tools/sch_link.py`, `tools/sch_seam.py`, `tools/sch_dial.py` and `tools/sch_expansion.py` (shared code in `tools/schlib.py`, kicad-sch-api in `.venv/`),
which refuse to overwrite a sheet that already has symbols unless run with `--force`,
and fail if KiCad's exported netlist differs from the nets they intended. Symbol UUIDs
are `uuid5("keyboard/<board>/<ref>")` (2026-09-15), so a `--force` rerun keeps PCB
footprints linked to their symbols. Mounting holes are schematic symbols
(`Mechanical:MountingHole`, not in BOM), so PCB schematic-parity reports nothing board-only.

`tools/check_interconnect.py` (2026-09-16) audits every JST GH header from the scripts'
`PARTS` tables: mated headers agree pin for pin through a per-pair net alias table
(`MATES`), with the same MPN; end-reversed, a power pin only faces its own net, and GND
facing a signal needs a `GND_SIGNAL_OK` reason; power nets have ≥2 contacts; pin counts
are unique per header type. Headers whose mate is on a keys-* board are listed in
`PENDING` until those schematics exist; an unlisted header is an error.

**Ownership (2026-09-15):** the `sch_*.py` scripts own every schematic sheet; change a
sheet by editing its script and rerunning it, never in Eeschema or with an MCP tool (the
next `--force` run would discard the edit). PCB layout (`.kicad_pcb`) is done in KiCad,
including through the Konnect MCP server, and no script touches it.

The link board is one PCB with two KiCad 10 design variants, `upstream` (also the
default population) and `downstream`. Export a population's BOM with
`kicad-cli sch export bom --variant downstream --exclude-dnp`; `sch_link.py` checks
both BOMs after writing. Its TPD6E05U06 uses the stock `Package_SON:Texas_R-PUSON-N14`
(14 × 0.75 × 0.2 mm pads, 0.5 mm pitch, columns at ±0.675 mm). **Accepted on the KiCad
library's citation (2026-09-14)**: its description cites TI's RVZ land pattern in an
older TPDxE05U06 datasheet (p. 28); not re-checked here, because datasheet rev O
dropped the RVZ drawing and TI's older revisions and package pages could not be downloaded.
**P14 (2026-09-15):** the downstream population fits U603 `TPS22950LYBH` from `J_LBD`'s
VBUS pins (`VBUS_LBD`, C603 1 µF) to the port, `ON` on `J_LBD` pin 6 (`LINK_SW_EN`), R605
624 Ω on `ILIM` (latch-off `IHCD` 1.2–1.9 A, SLVSFJ2B Table 7.5); `FLT` is not used. U603's
`VOUT` sits on `VBUS_CONN`, which R604 joins to `VBUS_LINK` downstream, so ERC never sees
U601's and U603's power outputs on one net; `VBUS_CONN` therefore carries no PWR_FLAG.

**Phase 3 (2026-09-15):** the upstream population's R603 `ISET` is 4.99 kΩ (1.82–2.18 A
latch, as on the USB port board); it was 1 MΩ (OCP disabled). The battery board adds R806
330 kΩ from `CELL+` to GND, so a hot cell swap cannot find the OVP FET still held on by C801
(ngspice deck `tools/sim/e14_pack_swap.py`; calculations in `tools/sim/phase3_calcs.py`).

The seam board has one variant per position: `left` (default population, 2 × spring
halves), `right-left` (2 × flat), `right-right` (pair A, spring) and `numpad` (pair A,
flat). The one-pair variants leave out J702 and U702; the flat variants override
`Value` and `MPN` only, since both halves use the same land pattern. `sch_seam.py`
checks every variant's references, values and MPNs in the exported BOM.

The expansion board (2026-09-15) has J1001 JST SM12B-SRSS-TB (stock footprint, checked
against JST eSH.pdf p. 1: pads 0.6 × 1.55 mm, MP 1.2 × 1.8 mm at ±6.8 mm), U1001
TPD4E05U06 (3V3, 5V, SDA, SCL; seam's DQA footprint), U1002 TPD6E05U06 (SCK, MOSI, CS,
DC, RST, INT; link's RVZ footprint), C1001/C1002 100 nF on 3V3/5V, and J1002 `J_EXP`
(GH 15). `J_EXP` is mirrored: 1/15 5V, 2/14 GND, 3/13 3V3, 8 GND, 4 SCL–12 SCK,
5 SDA–11 INT, 6 RST–10 MOSI, 7 DC–9 CS. The MP pads of both connectors have no symbol
pin, as on the other boards.

The core (2026-09-15) is one A1 sheet, refs 4xx, with KiCad 10 variants `tps61099` (default
population) and `max17222`; `sch_core.py` derives its intended nets from the pin tables (and
checks there is no single-node net), then checks both variant BOMs. The MAX17222 (U407) has no
footprint yet and feeds `V3P3_BOOST` through R426 0 Ω, fitted only in `max17222`, so ERC never
sees two power outputs on one net. C406, L401 (REG0, spec §15) and J401 (TC2030-NL, footprint
only) are DNP everywhere; JP401 is a bridged solder jumper (not in BOM, so the BOM check skips
library `in_bom no` symbols). PWR_FLAGs sit on nets fed only by connector pins, on `SUP_VDD`
(BAT54C), `VDDH` (jumper) and `SW_LOGIC` (the stock TPS61099DRV types SW as power input).
The stock `Regulator_Linear:TLV75733PDBV` is derived (`extends`), so the library has its own
`TLV75733PDBV`. Footprints not yet checked against a vendor drawing: crystal, SKRTLAE010,
PCM12, and the XEL4030 on the XAL4030 footprint (open question P18). `schlib.run` takes a
`paper` size (default A4).

The dial board (2026-09-15) uses `keyboard:RotaryEncoder_Switch_MP` so the PEC11R's
mounting lugs reach GND, `Device:D` for its 1N4148W (the stock `Diode:1N4148W` is
derived from `1N4001` and trips ERC `lib_symbol_mismatch` through kicad-sch-api),
and a DNP TPD4E1U06 (U901) on the encoder pins. `J_DIAL` is 1 SW_ROW, 2 ENC_A,
3 GND, 4 ENC_B, 5 SW_COL. Its PCB (trial route, provisional) passes DRC with
schematic parity at 0 errors and 0 warnings (2026-09-15): footprints match their
libraries, reference text is 0.8 mm / 0.12 mm, and the H901/H902 references are hidden.
Konnect could not refresh D901/U901 from the library (lossless-refresh limits), so
with KiCad closed, those two and the reference positions were patched once in the file.

Ref ranges are set with `annotate_start_num` in each `.kicad_pro`. Every project
is two copper layers until the Phase 4 stackup decision. Design-rule minimums are
0.127 mm track and clearance and 0.2 mm drill (0.15 mm on USB port and link).
Every empty board reports one DRC violation, "no board outline", until an
Edge.Cuts outline is drawn.

`common/` holds the shared key-board sheets (LED matrix, link routing), which are
still empty.

## Vendored `lib/kiswitch/`

A subset of [kiswitch](https://github.com/kiswitch/kiswitch) (MIT / CC-BY-SA 4.0),
copied by `tools/vendor_kiswitch.sh`; the commit is in `lib/kiswitch/VENDORED.md`.
The generator adds its two libraries to the `keys-*` projects' `fp-lib-table`:

- `Switch_Keyboard_Hotswap_Kailh`: Kailh MX hotswap (`CPG151101S11`), 1U–7U, plain
  and plated variants
- `Mounting_Keyboard_Stabilizer`: `Stabilizer_Cherry_MX_2.00u`, which covers 2U, 2.25U
  and 2.75U (23.8 mm)

Their 3D models live in `lib/kiswitch/3dmodels/` and resolve from projects one level
below `hardware/`.

Not in the library yet:

- The combined RGB LED footprint (spec §12, P1), which needs samples of the three LEDs.
- The MAX17222 µDFN-6 footprint (Maxim land pattern 90-0004).
- The TPS25947 (P7 candidate only, not chosen).
- A Keystone 2462 second-source holder footprint (P15), which needs Keystone's current drawing.
