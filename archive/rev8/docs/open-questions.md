| F7 | Module-controller firmware: framework, register map, update flow | The register map is the contract every comms pair must carry (spec §9): it must be versioned and fixed before a second comms medium exists. **Part decided (P19): MSPM0G3505**, whose ROM bootstrap loader runs on its default I2C pins, which carry the link, so the hub can reflash key boards over the link. **Hardware side decided 2026-09-29** (spec §9): software entry (`RESETLEVEL` = BOOTLOADERENTRY), the hub writes the vector table last so an interrupted update boots into the BSL (blank-device rule, SLAU887A §3.2.1), PA18 keeps TI's default `BSL_invoke` with a pull-down and a rescue pad; no NONMAIN changes. Open: image signing/versioning, the BSL password handling, the update procedure on the hub. Framework options: Zephyr (MSPM0 support at our pinned version not checked), TI's MSPM0 SDK, bare metal. The slot probe timings (E18: ~200 ms window, ~100 ms every ~2 s) are tuned on hardware | Draft map in spec §9 → reviewed spec → prototype on an LP-MSPM0G3507 LaunchPad with an IS31FL3733 | before key-board capture |
| F9 | Does ZMK at the pinned version support the TCA9548A and a custom `kscan` over it? | The hub's module discovery rests on Zephyr's I2C mux binding (`ti,tca9548a`, believed upstream, not checked at our pin) and on a custom `kscan` driver mapping remote key indices into one transform; the wake path needs the slot `INT` pins as wake sources | Source check at the pinned commit; dev-kit test with a TCA9548A breakout | week 1 |
| E16 | Does I2C run reliably through a USB 2.0 C-to-C cable's D± twisted pair? | SDA and SCL share one twisted pair, which couples SCL edges onto SDA; ~90 pF per line estimated, ~170 ns rise with 2.2 kΩ at 400 kHz (spec §6). **Approach decided 2026-09-26: design for 400 kHz, automatic per-slot fallback to 100 kHz on errors** (~100 vs ~33 full lighting frames/s); the register map carries a CRC or sequence check so the hub can count errors (F7) | Scope at both ends through 1 m cables from three makers at 400 kHz and 100 kHz; frame-rate soak with error counting (§16) | bring-up |

## Standing risks

These have no single answer; they are watched rather than closed.

- **Two firmware images** (hub ZMK, module controller). The module controller's
  register map is a contract; changing it later means updating every key board.
  Mitigated by versioning it from the start and an update path over the link (F7).
- **The link is I2C on a USB cable**, outside what I2C was designed for (E16). The
  fallbacks are a lower clock, a shorter cable, or a differential comms pair later.
- **The keyboard stops if the hub fails.** One board to swap; the build guide lists
  it as a spare.
- **TPS61023 has no pin-compatible second source.** Accepted; stock rechecked at
  Phase 6.
